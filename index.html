Distributed Bicycle & Banking System (Rust)

A fault-tolerant, concurrent distributed system built completely from scratch in Rust. The architecture coordinates a network of bike-sharing stations communicating over a logical ring, paired with a replicated banking cluster running a Two-Phase Commit (2PC) consensus protocol.

Systems Architecture & Concurrency

  • Actor-Based Concurrency (Actix): Built using the Actor Model for asynchronous message passing, ensuring thread-safe state isolation across stations, network dispatchers, and bank replicas without explicit low-level lock contention.
  • Distributed Consensus (2PC & Ring Elections): Implemented a partition-tolerant Two-Phase Commit protocol with majority quorums for bank transactions, alongside a self-healing ring topology featuring automated leader election algorithms.
  • Custom TCP Multiplexing Protocol: Designed dual-port TCP listeners per station for internal network rings and client CLI handling, processing raw binary frames and structured JSON payloads asynchronously via Tokio.

Tech Stack: Rust, Actix Framework, Tokio (Async Networking), Serde (JSON/Binary Serialization), TCP Sockets.
